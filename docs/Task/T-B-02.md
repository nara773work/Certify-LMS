チケットID:T-B-02

大量データを分割処理していると、途中でデータの状態が変更されてデータを取りこぼすことがある。
今は「状態」で絞り込んでいるため取りこぼしが起きる可能性がある。
定期実行処理なので、Command周りを調べる。

## 変更を加えるファイル
- GraduateExpiredUsersCommand(プラン期間の満了処理)
- FailExpiredEnrollmentsCommand(学習中止)
- Mentoring/AutoCompleteMeetingsCommand(終了時刻過ぎの面談)

## 調査の足取り
ユーザーを3人とる → 修了にする → ユーザーを3人とる → ・・・
を繰り返している
checkでは、「学習中ステータスのユーザーを3人とったら、次の3人は学習中ステータスの人を3人飛ばして（オフセットをとって）次の3人を取得する」というとり方でデータを取得する。
123とる → ステータス変更（終了） → 学習中ステータスは456789・・・と並んでいるので、3人飛ばすと789をとってしまう。
つまり、ステータスを変更してから次に取る人を確認しているので取りこぼしが起きてしまう
chunkByIdなら、IDで順番を確認するのでこちらを実装するように修正する。
